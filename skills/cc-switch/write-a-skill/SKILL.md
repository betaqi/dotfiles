# 编写 Skill

## 流程

1. **收集需求** — 询问用户：
   - 这个 skill 覆盖什么任务/领域？
   - 需要处理哪些具体用例？
   - 是否需要可执行脚本，还是只需要指令？
   - 有没有要包含的参考材料？

2. **起草 skill** — 创建：
   - SKILL.md，包含简洁指令
   - 如果内容超过 500 行，拆分为额外的参考文件
   - 如果需要确定性操作，添加工具脚本

3. **与用户评审** — 展示草稿并询问：
   - 这覆盖了你的用例吗？
   - 有遗漏或不清楚的地方吗？
   - 哪些部分需要更详细/更简略？

## Skill 结构

```
skill-name/
├── SKILL.md           # 主指令（必需）
├── REFERENCE.md       # 详细文档（如需要）
├── EXAMPLES.md        # 使用示例（如需要）
└── scripts/           # 工具脚本（如需要）
    └── helper.js
```

## SKILL.md 模板

```md
---
name: skill-name
description: 简要描述能力。当 [具体触发条件] 时使用。
---

# Skill 名称

## 快速开始

[最小可运行示例]

## 工作流

[带检查列表的分步流程，用于复杂任务]

## 高级功能

[链接到单独文件：参见 [REFERENCE.md](REFERENCE.md)]
```

## Description 要求

Description 是 **agent 在决定加载哪个 skill 时唯一能看到的信息**。它出现在 system prompt 中，与所有其他已安装 skill 并列。Agent 读取这些 description，根据用户请求选择相关 skill。

**目标**：给 agent 刚好足够的信息来判断：

1. 这个 skill 提供什么能力
2. 何时/为何触发它（具体的关键词、上下文、文件类型）

**格式**：

- 最多 1024 字符
- 用第三人称
- 第一句：做什么
- 第二句："当 [具体触发条件] 时使用"

**好的示例**：

```
从 PDF 文件中提取文本和表格，填写表单，合并文档。当处理 PDF 文件或用户提到 PDF、表单或文档提取时使用。
```

**差的示例**：

```
处理文档。
```

差的示例让 agent 无法把它和其他文档类 skill 区分开。

## 何时添加脚本

在以下情况添加工具脚本：

- 操作是确定性的（校验、格式化）
- 同样的代码会被重复生成
- 错误需要显式处理

脚本比生成代码更省 token、更可靠。

## 何时拆分文件

在以下情况拆分为单独文件：

- SKILL.md 超过 100 行
- 内容涉及不同领域（如 finance vs sales schema）
- 高级功能很少被使用

## 评审检查清单

起草完成后，验证：

- [ ] Description 包含触发条件（"当……时使用"）
- [ ] SKILL.md 不超过 100 行
- [ ] 没有时效性信息
- [ ] 术语一致
- [ ] 包含具体示例
- [ ] 引用深度为一层
